# 声明式插件 API v2：图文导出

本参考对应 `src/plugins/sdk/types.ts`、`manifest.ts`、`exportTypes.ts` 及宿主图文导出实现。v2 新增数据形式的 `exporters`，由核心提供统一界面和静态排版，不执行第三方 JavaScript、HTML 或 CSS。v1 内容插件继续使用[原契约](API_V1.md)；外部宿主通信仍为 v1。

## 清单与贡献

`manifestVersion` 与 `apiVersion` 必须同时为 `2`。身份、名称、说明、包实现版本、能力和工作区字段沿用 v1 规则，拒绝未知字段。`contentTypes` 仍为必填数组；存在有效 `exporters` 时可以为空，其他情况至少提供一个内容类型。v2 可以同时提供内容类型与导出贡献。

`exporters` 若出现，须为 1–16 项。每项必填且只允许：

- `id`：插件内唯一的稳定标识，沿用插件 ID 的安全字符规则，最多 128 字符。
- `label`：导出菜单名称，非空，最多 100 字符。
- `description`：说明，非空，最多 4000 字符。
- `templates`：1–16 套视觉模板，各自 ID 唯一。
- `presets`：1–16 组画幅预设，各自 ID 唯一。

API v1 清单仍拒绝 `exporters`，不能只把 `apiVersion` 改为 2 而保留 `manifestVersion: 1`。内容类型继续按 provider、类型与内容版本独立校验。允许的能力仍只有 `context.read` 和 `content.open`，含义没有变化；纯导出模板声明 `capabilities: []` 即可。

## 视觉模板与预设

参数模板精确包含以下字段：

```json
{
  "id": "paper",
  "name": "简洁纸张",
  "background": "#FFFFFF",
  "textColor": "#243247",
  "headingColor": "#15253D",
  "accentColor": "#2563EB",
  "fontFamily": "sans",
  "fontSize": 32,
  "lineHeight": 1.65
}
```

`id` 为稳定标识，`name` 非空且最多 100 字符。四个颜色只接受六位 `#RRGGBB`，不接受 CSS 表达式或资源 URL。`fontFamily` 只接受 `sans` / `serif`，由宿主选择本地字体；`fontSize` 为 16–80 的整数，`lineHeight` 为 1.2–2.4 的有限数。

用户可在宿主“样式”中导入 TTF、OTF、WOFF、WOFF2 字体，原件按所属资料库保存、复用和下载。这是宿主设置，不新增清单字段；插件不能声明本地字体 ID、读取用户字体库、加载远程字体或获得新的能力。`fontFamily` 的清单取值保持不变。

也可引用当前宿主的共享文档样式，此时精确包含三个字段，不能混入上述颜色或字号字段：

```json
{ "id": "native", "name": "跟随正文", "style": "document" }
```

`style` 只允许精确字符串 `document`，不能传 CSS、文件路径、对象或其他主题名称。该形式对官方和社区包同样开放；宿主通过 `publicationTheme.ts` 解析默认参数，复用网页只读内容组件，以 `src/styles/documentTheme.ts` 和自动聚合的应用 CSS 保持正文外观同步。旧的完整参数模板保持原行为，不会被自动改成文档样式。尚不支持该形式的旧版 MeWiki 会严格拒绝新清单。

渲染选项通过可选 `style: "document"` 保留引用；旧请求和旧个人模板不补该字段。当前基础模板使用共享主题默认值，个人模板保存实际参数快照；基础排版修复仍可能改变新生成的图片，已下载文件不会改变。

每个预设精确包含 `{ "id": "portrait", "name": "纵向画幅", "width": 1080, "height": 1440 }`。宽为 480–2160、高为 480–12000 的整数。名称不是平台上传保证；实际导出仍需满足单张 1600 万像素与正文可用空间检查。

宿主将清单模板显示为“系统模板”，与“个人模板”共用一个分组选择框。选择系统项时，从宿主完整默认参数、该导出器的首个画幅预设及模板声明重新构建整套配置，不沿用上一个模板的作者、封面、尺寸或图片格式；图片创作中选择系统项会保持图片模式并重置画布。选择个人项则恢复其完整保存值。用户可继续修改并保存；恢复操作重载当前选中项，复制和导出使用该项的保存值。本次笔记的标题、内容选择和手动分页不属于模板。此为宿主交互约定，不新增清单字段；模板文件的画布 v2 扩展见后文。

清单不接受远程字体、资源路径、脚本入口、原始 HTML/CSS、任意表达式或插件自己提供的排版代码。

## 完整包与作者流程

独立示例见[发布模板](../../examples/plugins/publication/manifest.json)，官方模板见[社交图文导出](../../plugins/social-export/manifest.json)。作者可复制示例到独立仓库并修改身份、版本与参数：

```sh
npm run plugin:validate -- examples/plugins/publication/manifest.json
npm run plugin:pack -- examples/plugins/publication .mewiki/publication.mewiki-plugin
```

包安装、摘要、不可变版本、回滚和卸载复用现有流程；包内仍只允许清单、说明与许可文件，沿用 v1 的包大小和路径限制。个人模板 JSON 与插件安装包是两种不同文件，分别从图文导出窗口和插件管理页导入。

核心按贡献类型处理模板，不按官方 ID 或平台品牌分支。用户启用插件后，其 `label` 出现在“更多笔记功能”菜单；点击后在独立浏览器标签页打开完整导出界面，原页保留笔记供比对。`PublicationPage.tsx` 校验固定快照与插件状态，`PublicationDialog.tsx` 提供模板、参数、预览和下载工作区。

宿主默认在中间显示随配置更新的虚构样板，用户切换到完整原文后逐块勾选并设置此前分页，生成后查看真实结果。样板与正式输出共用核心静态排版模块，在无脚本 iframe 中显示，不启动后台图片任务；实际分页和资源完整性仍以生成结果为准。尺寸界面优先使用画面比例与清晰度，最终仍转换为原来的宽高、字号和留白参数；高级精确尺寸、清单预设、个人模板 v1 和请求格式均保持兼容，不新增插件字段。

宿主自动把工作配置、正文选择及图片创作原件与逐图调整保存在当前浏览器的隔离工作草稿中，刷新和重新打开可继续；草稿不包含笔记正文或成品，不改个人模板、不隐式新建命名作品。草稿以稳定库、插件、导出器、笔记、入口和会话分区，插件没有枚举或读取草稿的接口，宿主 v1、插件 API 和资料格式均不扩权。长期备份仍用个人模板及图片作品包。

## 内容范围与静态化

宿主固定用户当前笔记快照，允许勾选顶层内容块；默认选择整篇。`style: "document"` 直接复用网页只读组件，保留标题编号、引用图标与粗体、Callout 自定义外观、标签页、公式与脚注、媒体与附件卡片。当前标签页和已显示 PDF 的阅读页码只固定在导出快照中；PDF 未显示时使用保存页码，默认第一页。音视频为静态卡片，视频优先使用本地封面，PDF 页图、流程图、手绘和图表均静态化为图片。参数模板仍经 `publication.ts` 使用简化排版。网络图片、缺失原件、失效引用与无法静态化的内容明确报错；未知外部内容仅导出通用可读字段。

原生内容和前端共用组件与 CSS，构建自动聚合全部样式到 `mewiki-publication.css`。应用更新、重新构建并重启服务后，重新打开导出生成即使用新版样式，个人参数保持保存值。内部受限 DOM 树仅是宿主的实现数据，不是插件贡献字段；清单仍不得携带 HTML、CSS 或代码。代码、表格等若需要内部滚动才能显示完整，静态输出无法容纳时明确拒绝，不能导出裁切结果。

模板插件不取得整库状态、真实目录或文件读取接口，也不能后台扫描笔记。主页面只通过当前资料库现有的附件服务取得选中资源，再传递静态 PNG/JPEG 数据。宿主 v1 不新增笔记读取或图片导出权限。

本地渲染器使用 `playwright-core` 调用已安装的 Microsoft Edge，独立浏览器上下文不加载主应用，阻止任意网络和本地 API 请求。文档样式默认跟随 MeWiki 的本机正文字体，其他参数模板使用本地 Noto Sans SC / Noto Serif SC，公式字体来自 KaTeX；不请求远程字体，输出尺寸按最终像素计算。

表格正文、表头、普通引用与代码使用实色底层，原生数据表同样具备白色底层；背景纹理不会透过这些内容。普通表格、数据表与参数模板共用深墨蓝表头、明亮标题文字和浅色链接，外框与全部行列分隔线使用相同深墨蓝；正文保持白底深字，分页重复表头保留配色。代码在原生与参数模板中统一采用宿主近黑终端配色和本地深色语法高亮，未知或未指定语言安全转义后显示浅色原文。Callout 和标签页保留自身配色。该样式约定不增加插件清单参数或任意 CSS 接口。

## 宿主服务与限制

宿主支持图片导出，沿用同一个导出器、个人模板和设备渲染体系，不增加插件清单字段或宿主读取权限。渲染选项可选 `imageMode: { fit: "contain" | "cover" }`；存在时，每个 `kind: "image"` 静态块生成一张固定尺寸图片，只接受图片块，不走正文分页。图片块可选 `crop: { x, y, zoom }`，`x/y` 为 0–100、`zoom` 为 100–300 的整数；仅 `cover` 应用取景，`contain` 完整居中。服务逐项校验并保留序号诊断。没有 `imageMode` 或 `crop` 的旧请求与个人模板不补字段。

图片模式将无关正文选项规范为默认值、强制 `mode: "pages"`，忽略正文空间检查与正文字体、头像、封面资源；有效纹理范围规范为 `all`，统一位于屏幕背景。画幅、格式、质量、背景、纹理及设备配置继续严格校验；所有设备外壳与连续圆角复用正文导出的共用函数。没有文字图层时不加载无关字体；文字图层使用下述受限画布字体。预览和最终结果使用同一静态页面构造器。

宿主界面可从当前冻结笔记的图片块、Markdown 图片、所有标签页及选中的同库内容引用收集候选，或由用户一次选择多个本地文件；不扫描任意插件 JSON、不读取未引用笔记的附件，不自动下载网络图。原件按当前库读取，本地选择文件不写入笔记附件；用户显式保存图片设计后才复制到隔离的作品素材区。每批最多 50 张、最终合计 8000 万像素、成品总量 32 MiB；按既有正文数据预算懒读取并串行拆成任务组，固定同一套参数、选择顺序和逐图取景。失败或取消后不启动后续组，全部成功后才发布批量结果。

个人模板 v1 保存 `imageMode` 与共用参数，不包含本次源图、选择列表或 `crop`；图片模式模板不附带无关字体、头像或封面原件。ZIP 使用序号和来源名称保存每张成品，不生成正文配套文案。

### 宿主图片创作画布

图片创作与笔记导出为两种主要模式，可从插件管理或笔记更多菜单独立打开，不携带笔记正文。该能力由统一 exporter 执行器提供，不按官方插件 ID 分支，也不扩展插件清单或宿主通信权限。

内部 `PublicationOptions` 可选 `composition: { version: 1, subject, layers }`，仅允许图片模式。**宽高只来自原有 `width/height`；composition 不接受自己的画布尺寸。** 主体包含 `x/y/scale/rotation/hidden/locked`；最多 40 层文字、系统 SVG 贴纸或本地 PNG/JPEG 装饰图。位置与宽高按父空间百分比，文字大小按父空间短边比例保存。图层在 `canvas` 或 `screen` 中定位，后者随设备整体变换；同空间按列表顺序叠放，画布图层在主体上方。

每层支持稳定 ID、名称、位置、宽高、旋转、透明度、显隐、锁定，以及严格限定的颜色、字重、字体、行距、对齐、底色、圆角、内边距等。禁止任意 CSS/HTML、远程资源、表达式、原型字段和未知字段。装饰图内联数据每层最多 3 MiB、共用场景合计最多 8 MiB。`PublicationBlock.imageData` 可选固定 `title/subtitle/name/index/total/overrides`；只替换 `{{title}}/{{subtitle}}/{{name}}/{{index}}/{{total}}` 文字变量，逐图覆盖以稳定层 ID 和属性白名单合并。未覆盖的属性继续继承共用层，切换模板清除层覆盖、保留本批原件、取景和文案。

请求可选 `fonts: PublicationFont[]`，仅携带画布实际所需的资料库字体，全批最多 8 种，每种原件上限仍为 100 MiB。旧单正文字体 `font` 继续兼容；无画布的旧图片请求不补 composition 或 fonts。字体由当前库读取并验证摘要，模板插件本身无权枚举或读取字体。

`publicationImagePages.ts` 与 `publicationCompositionLayout.ts` 共用预览和最终静态 DOM；等待字体后进行文字自动缩小与旋转边界校验。仍不能放入时返回“图片创作 → 第 N 张 → 第 M 个图层”路径，界面切回实际图片和图层，不发布部分结果。跨任务组传递全批 index/total，串行懒读取和原有成品预算不变。

包含画布的个人模板交换使用 `mewiki-export-template` **version 2**，保存共用 scene、固定装饰和 `fonts[]`；不包含批次主图、文案或逐图覆盖。无画布模板仍输出 version 1，新宿主兼容旧模板。模板文件总量继续受 140 MiB 限制。

`ImageDesign` 保存 options、已选原图的稳定资源摘要、逐图 crop/imageData；`PersonalSticker` 单独收藏素材。二者由 `/api/mewiki/image-workspace` 的 GET/PUT 及 `/assets` GET/POST 提供本机接口，固定请求头 `X-MeWiki-Request: image-workspace`，拒绝非回环或跨来源请求。存储按 `(libraryId, pluginId)` 摘要目录隔离，默认 `.mewiki/image-workspace/`，隔离测试使用 `<设置文件>.image-workspace/`。配置写入使用 revision、锁和临时文件原子替换；原件按 SHA-256 去重并复验。每库/插件最多 32 作品、200 贴纸、32 MiB 配置和 1 GiB 原件；删除或停用不清理原件。

首次显式保存后约两秒自动保存；失败暂停自动重试并保留错误。作品备份为 `mewiki-image-design` version 1 的 ZIP：manifest、去重原图和字体，总量最多 512 MiB。导入严格限制条目、路径、解压流大小与摘要，成功后登记新作品，不覆盖既有作品。图片创作存储不在笔记备份内，使用者需另行导出作品包。操作和示例见[图片创作手册](../wiki/20-social-export.md#在画幅内添加文字和贴纸)。

以下为 MeWiki 界面与本地服务之间的接口，不是插件可执行 API：

- `/api/mewiki/publications/jobs`：`POST` 创建任务，`GET /<任务 ID>` 查询进度和结果，`DELETE /<任务 ID>` 取消或释放。请求使用 `X-MeWiki-Request: publications`，创建请求为 JSON。
- `/api/mewiki/export-profiles`：`GET` 按 `library` 与 `plugin` 读取，`PUT` 以 `libraryId`、`pluginId`、`revision`、`profiles` 保存个人模板。请求使用 `X-MeWiki-Request: export-profiles`，写入为 JSON；旧修订冲突拒绝覆盖。
- `/api/research-library/media/fonts?directory=...`：由当前登记目录返回字体附件元数据，上传、内容读取、备份与恢复沿用附件接口。宿主按稳定库 ID 查询当前绑定，导出页的笔记快照不会固定字体的保存位置。

渲染选项可含 `fontAssetId`（64 位小写 SHA-256）；任务请求相应携带 `font: { id, name, dataUrl }`。两处摘要必须匹配，资源只接受 `data:font/ttf|otf|woff|woff2;base64,...`，单原件最多 100 MiB，并验证格式头、表边界及摘要。未选用户字体的旧请求不补字段；不接受第三方 URL、路径、字体 CSS 或任意字体名。

接口只接受本机当前页面的请求，不向外部宿主或插件 iframe 开放。单次渲染请求（含内联字体）最多 160 MiB；其中正文内容仍最多 32 MiB，最多 1000 个静态内容块、正文总量最多 200000 字符。嵌在复杂 Markdown 结构中的图片以内联 PNG/JPEG 保留位置，单个含图结构最多 180000 字符，超出时要求压缩或改用独立图片块。单张最终图片 1600 万像素、最多 50 页、总计 8000 万像素、图片成品总量最多 32 MiB、90 秒超时。同一本地服务仅允许一个活动渲染任务，完成或取消释放浏览器后才开放下一项。

主页面导入的源图片上限为 8 MiB、1600 万像素，支持将可读的本地 WebP/GIF 转成静态 PNG。渲染服务对直接传入的 PNG/JPEG 另做解码、静态页数和大小检查，上限为 9 MiB、2400 万像素且仅接受一帧；前端更紧的限制仍是普通用户操作上限。

个人模板最多 20 份，按 `(libraryId, pluginId)` 隔离；默认持久目录为 `.mewiki/export-profiles/`，隔离设置使用 `<设置文件>.export-profiles`，文件名由这两个稳定 ID 的摘要生成。一次保存最多 32 MiB。日常字体配置只保存 `fontAssetId`；用户导出文件使用 `format: "mewiki-export-template"`，无画布为 `version: 1`，含画布为 `version: 2`，包含实际参数、内联固定图片及可选的 `font` 或 `fonts[]`，不包含笔记正文或批次主图。字体必须与参数匹配，导入先保存字体原件；旧无字体文件保持兼容。导出和界面导入整体文件上限为 140 MiB，解析函数另检查 140 × 1024 × 1024 字符上限。插件卸载保留配置，资料库备份不自动打包这些配置；字体原件作为资料库附件进入完整 ZIP，JSON 快照不含原件。

`exportProfileLock.ts` 使用带进程身份和唯一标识的声明文件串行处理跨进程保存，在持锁后重新检查修订并原子替换；陈旧修订拒绝覆盖，已退出进程的声明可以回收。相邻存储测试覆盖同目录的独立服务实例并发写入。

渲染选项和个人模板可选 `frame: { id, background, scale, shadow, contentScale }`。`id` 仅接受宿主内置 `phone`、`phone-landscape`、`laptop`、`browser`；背景为六位十六进制颜色，`scale` 为 60–100、`shadow` 为 0–100、`contentScale` 为 75–125，均为整数百分数。没有字段表示无边框，不接受 `null`、URL、CSS 或其他自定义属性。设备在当前输出宽高中同比居中，屏幕内正文按逻辑空间分页，每页及封面各自生成设备层；最终输出尺寸和像素上限不变。连续长图保留参数但跳过设备层，切回分页恢复。系统素材由宿主本地提供，个人模板 v1 只存参数；这不是新增的插件清单贡献或宿主权限。

校验失败继续通过原有 `error` 字符串返回，内容为“设置路径或静态内容项序号：具体原因与调整方法”。尺寸范围、正文空间、设备参数、纹理层与图片来源分别定位；服务端图片解码和公式排版保留来源上下文，不回显正文、文件路径或资源数据。界面只在显示边界翻译系统标签和错误模板，插件不能依赖中文提示作为机器可读的错误码。

正文静态项可选 `sourceId: string`（1–1000 字符），记录其所属的顶层原文选择项；同一个原文项展平后的多个静态项可共享该值。原有 `id` 仍是唯一静态项身份，旧请求不要求 `sourceId`。它不是笔记资料字段或模板参数，不新增插件清单贡献点。

当实际图片排版检测到滚动裁切或某项无法分页时，错误任务可附 `diagnostics: { blockId: string, code: "horizontal-overflow" | "vertical-overflow" | "page-overflow" }[]`。`blockId` 精确匹配本次请求的静态项 `id`，不是数组下标或 `sourceId`；界面使用本次冻结文档的 `sourceId` 将其映射回原文选择项。客户端只接收本次静态项白名单内的已知代码并去重，旧服务的纯 `error` 显示方式保持兼容；不要从错误字符串提取机器码。

滚动裁切在完成分页后合并报告已检测到的问题项，拆页后的同项/同方向只报告一次；单项无法分页时可能提前停止，先报告使排版停止的内容。封面、页眉页脚、长图总高度、页数和像素限制等全局错误不附正文诊断。来源和诊断不携带正文片段、附件数据或目录，不扩展 v1 宿主协议或插件数据读取权限。修改模板参数、选择、页签或 PDF 页码后清除旧标记，须重新生成才能检查新配置。

## 生命周期与后续能力

宿主的“样式”设置另提供八种本地背景纹理、图片制纹理及最多 6 层叠加。个人模板可选旧单层 `options.texture` 或新 `options.textureLayers` 数组，两者互斥；数组顺序为前层在先，空数组表示无纹理，界面在单层时继续保存旧形态。每层包含受限的预设、颜色、强度、大小、质感、方向、范围、种子和内联自定义 PNG/JPEG；范围为 `all`、`body`、`cover` 或 `margins`，其中 `margins` 只覆盖每页四周 `options.margin` 宽度的区域，包括长图的实际四边。每层自定义图片最多 2 MiB 字符，所有层的图片合计最多 8 MiB 字符，仍受模板和请求整体上限约束；每层素材均参与服务端图片校验。没有纹理字段的旧模板继续按无纹理读取。

纹理不是插件清单贡献字段，插件不能提交自定义 SVG、CSS、外部 URL 或处理代码。预设由宿主确定性生成；用户图片只在本机裁切和处理。样板和正式分页从同一静态模板克隆背景图层，保存/导入/导出个人模板包含层序、参数和已应用素材，不改变宿主 v1 权限。

生成、预览和下载共用固定快照与图片结果，导出页按打开时的资料库固定身份；来源页切换笔记或资料库不改变该快照。关闭或离开导出页、停用、卸载或切换插件版本终止旧会话，迟到结果不得进入其他页面。刷新仍使用当前标签页临时保存的快照，复制 URL 到其他标签页不会读取笔记；获得最新内容需从笔记重新打开导出。当前无任意代码宿主、通用命令注册、面板注册或导入器。

API v2 数据导出是 P1 后的独立扩展，不要求先开放 P2 可执行运行环境，也不代表 P2/P3 已全部完成。HTML、PDF、平台账户发布及自由画布仍是后续方案，参见[阶段路线](../plans/2026-11-10-plugin-ecosystem.md)。

# MeWiki 开放集成接口

MeWiki 是笔记功能的唯一实现与资料保存方。外部程序通过公开 SDK 嵌入同一应用、提供当前内容，并响应用户点击内容卡片后的打开请求。WebBench 仿真回放是第一个可选插件。

## 开发归属

- 编辑、公式、词典、媒体、资料库与插件宿主只在 MeWiki 中开发。
- 外部程序只维护自身数据到外部内容的适配，以及定位/打开自身内容的操作。
- 每个插件通过统一清单声明内容类型、版本、结构、表单、视图与来源规则，不反向导入外部程序源码。
- 随附插件和独立安装的声明式包共用契约与安装流程：内容使用 API v1，图文模板使用 API v2，在“设置 → 插件与集成”中管理。独立包可从 JSON / ZIP 文件安装、更新和切换已安装版本；不会执行任意脚本。

本文是外部宿主 v1 接口说明，继续兼容现有连接。声明式插件开发和本地安装见[开发入口](../plugins/README.md)、[API v1](../plugins/API_V1.md)与[图文模板 API v2](../plugins/API_V2.md)；可执行运行隔离、通用编辑器贡献点与社区分发见[生态设计](../plugins/ARCHITECTURE.md)和[阶段路线](../plans/2026-11-10-plugin-ecosystem.md)。宿主 SDK 不提供读取笔记、注册编辑器命令或动态安装插件的能力。

导出页面的配置和图片创作工作草稿由 MeWiki 按资料库及笔记在当前浏览器保存，刷新或重新打开可恢复。草稿不通过宿主 v1 或插件接口暴露，不写回笔记、外部上下文或个人模板，不改变任何来源打开权限；操作与备份区别见[导出手册](../wiki/20-social-export.md#自动保留本次设置)。

## 内置 AI 与宿主边界

AI 工作区由 MeWiki 用户启动，使用用户自配的 API 地址、Key、协议和模型。用户选定的本库范围经核心工具读取，建议需显式审阅应用；AI 不获得宿主 v1 消息的触发权，不自动插入外部上下文、打开来源或调用外部程序。外部内容只向模型提供可读标题、摘要与备注，未知插件数据在资料交换中保留但不发送给模型。密钥与 AI 会话不进入笔记备份，不增加插件或宿主读取笔记、密钥、其他资料库的权限。使用与限制见 [AI 手册](../wiki/22-ai-workspace.md)，维护见 [Agent 架构](../ai/ARCHITECTURE.md)。

AI 工具参数的流式片段仅用于 MeWiki 中央的暂态渲染预览，不通过宿主或插件协议传播，不写笔记、历史或会话。只有完整建议经用户批准后才走现有保存流程；停止或切库丢弃未完成片段。此能力不扩充宿主 v1、插件 API 或资料交换格式。

原生 Agent 操作覆盖 MeWiki 内部笔记、内容块、标签页、词典及地图，仍由核心授权、先读取后提议、用户批准保存和安全撤回。同一笔记的待审修改可在一个页面累积展示并一次批准，也可在修改附近逐项同意、拒绝或调整后再同意；右侧保留建议状态和撤回入口。拒绝与调整仅保存在本库会话，只有明确同意才写入笔记；标签切换只影响本次预览，不通过宿主传播。外部来源仅开放可读标题、摘要、备注及允许的备注修改、移动或删除建议；不能创建外部来源块或改写插件私有字段。附件只允许引用本次授权笔记中已知资源，不能上传或删除原件。原生操作不增加宿主消息、插件权限或外部程序的自动触发入口。

## 图文导出与宿主边界

图片导出沿用此工作区：用户可从当前笔记的图片、Markdown、标签页与同库引用中选择，或主动添加多个电脑文件，共用一个模板与设备外观，每张一张成品。模板保存图片模式和共用样式，本次原图与逐图裁切仅保留在当前会话，不自动写入笔记或资料库，也不向宿主发送。批量按现有预算串行处理，取消或失败停止后续组；此能力不新增 v1 消息、插件读取权限或外部资源访问，详见[图片模式契约](../plugins/API_V2.md#宿主服务与限制)。

用户点击导出入口后，完整导出界面在独立浏览器标签页打开，原页保留笔记。新页固定当前库与笔记快照，解除对原页的 `opener` 引用，不挂载笔记写入控制器；地址仅包含稳定库 ID 和随机会话标识，正文和目录不进入 URL。来源页切笔记或切库不改变导出内容，这不扩展外部宿主的访问能力。

“社交图文导出”由 MeWiki 用户从笔记菜单启动。模板只声明画幅和样式，核心读取用户选定的本库内容、解析本地资源并在本机 Edge 排版；外部宿主不接收笔记快照，也不获得调用导出任务或个人模板接口的授权。导出中的外部内容只保留通用标题、摘要和备注，未知插件原始 JSON 仍在资料交换中完整保留，但不会自动放入发布图片。

默认“MeWiki 原生”模板直接复用前端只读内容组件，构建时自动聚合全部应用 CSS；官方与独立插件都可用 `style: "document"` 引用，不能传入任意 CSS 或代码。标题编号、引用图标、Callout、标签页及媒体卡片共用正文实现；图片、图形、PDF 页图和视频封面转换为静态图片。只读资源上下文不启动笔记写入会话，内部受限 DOM 不向插件开放。更新应用、构建并重启服务后重新打开导出生成，即使用新版正文样式；个人模板参数和已下载图片保持原值，不包含宿主容器、编辑按钮或侧栏。

正文表格、数据表、普通引用与代码具备实色阅读底层，避免导出背景纹理透入。网页与所有导出模板共用深墨蓝表头及同色外框、行列分隔线，搭配明亮标题文字与白色表格正文，以及近黑终端代码配色和本地语法高亮；Callout、标签页及媒体继续保留自身设定的底色。此为宿主样式更新，不增加清单字段、第三方 CSS 或宿主权限。

插件 API v2 不改变 `mewiki.integration` v1 消息、`context.read` 的方向或 `content.open` 的用户点击要求。个人导出模板属于按库配置，含内联作者图片的 JSON 可独立迁移；它不改变 `webbench-research-library` 资料格式，也不自动混入既有资料备份。使用说明见[社交图文导出](../wiki/20-social-export.md)。

导出窗口将系统与个人模板合入一个分组选择框，切换时恢复整套导出参数，用户随后可继续修改并保存；模板管理操作集中在顶部入口打开的图标与文字菜单，原生控件使用浏览器自身的焦点反馈。该界面调整不新增宿主消息、权限或模板文件字段，本次笔记的标题与内容范围不写入模板。

导出中间默认显示随当前配置更新的虚构样板，可切换到完整原文勾选内容和分页，或查看生成后的真实图片。样板与正式输出共用核心静态排版，不调用后台图片任务；比例和清晰度转换为原有精确参数，旧模板继续兼容。这些操作不写回笔记，也不向宿主增加消息或数据访问权。

导出左侧按“内容、画幅、样式”提供独立折叠的设置区。标题、作者信息与正文选择入口归内容，规格归画幅，字体配色和封面图片归样式；正文选择仍使用中间原文视图，分类调整不改变插件清单、个人模板格式或宿主协议。

“画幅”另提供手机、横屏手机、笔记本及浏览器窗口边框，使用本地固定外壳和屏幕布局。每页在当前输出尺寸中独立套框，原生正文仍复用网页样式，纹理留在屏幕内；长图暂不套框。参数随个人模板单独保存，不写入原笔记或资料交换格式，不增加外部宿主消息、资源读取权或插件执行能力。操作见[设备边框手册](../wiki/20-social-export.md#给宣传图片套上设备边框)。

导出校验错误会显示具体设置路径、纹理层或静态内容项及调整建议，图片解码和公式错误也保留来源。此为 MeWiki 本地导出界面的排错改进，仍沿用原有任务 `error` 字符串，不新增 v1 宿主消息或数据访问权限；操作见[导出错误定位](../wiki/20-social-export.md#无法导出时如何定位问题)。

实际导出排版发现滚动裁切或内容无法分页时，任务可在 `error` 之外返回结构化 `diagnostics`，由本次静态项 ID 映射回用户勾选的原文项。界面自动打开“选择内容”，标记问题、显示原文序号并支持定位；修改配置或范围后清除旧诊断并重新生成。静态项的可选 `sourceId` 仅用于这一来源映射，嵌套内容归属其整项选择；不新增宿主消息、笔记字段或模板字段。来源和诊断只在当前本机导出会话传递，详见[API v2](../plugins/API_V2.md)和[使用说明](../wiki/20-social-export.md#在原文中找到超宽或超高的内容)。

## 稳定的外部内容格式

笔记中的术语引用继续由 MeWiki 按稳定词条 ID 解析，每处独立选择名称、英文名称、中英文缩写或具体别名（包含英文别称），用户可重复引用同一词条并手动组合文字。插入与编辑面板共用类型说明和本次显示预览；该调整沿用既有引用参数，不改变 v1 宿主协议、资料版本或外部内容结构。操作见[术语引用手册](../wiki/05-symbol-dictionary.md#选择术语引用形式)。

```json
{
  "provider": "org.example.instrument",
  "contentType": "measurement",
  "schemaVersion": 1,
  "title": "本次测量",
  "summary": "可在未安装插件时阅读的摘要",
  "data": { "recordId": "record-1", "time": 0.125 }
}
```

`provider` 是插件的稳定标识，`contentType` 标识该插件内的内容类型，`schemaVersion` 只描述这份内容的结构。内容为 JSON，禁止函数和可执行代码；媒体、大型结果和原始记录通过引用传递。标题与摘要用于无插件时阅读。

现有通用校验位于 `src/integrations/externalContent.ts`：provider 与内容类型为至多 128 字符的标识，版本为正安全整数，标题非空且至多 1000 字符，摘要至多 8000 字符；`data` 为普通 JSON 对象，其内部遍历深度至多 20，拒绝非有限数值与危险原型键。整体大小实际按 `JSON.stringify(content).length <= 256 * 1024` 限制，口径为 JavaScript 字符串长度，不是 UTF-8 字节数。维护 v1 时保留现有校验行为；未来包大小与消息字节配额另行定义。

插入笔记后，MeWiki 增加 `id`、`type: "external"` 与用户备注 `note`。未知插件和未知内容版本依然保存原始 JSON、标题、摘要和备注；停用或卸载不删除卡片。Markdown、完整备份和含附件备份都保留该结构。插件应提供版本迁移，不得静默丢弃旧数据。

## 外部网页接入

启动 MeWiki 后，从它自己的服务加载 SDK，无需复制编辑器源码，也不要复制 SDK 实现。

```js
const { connectMeWiki } = await import(
  'http://127.0.0.1:5280/integration/mewiki-host.js'
);
const connection = connectMeWiki({
  iframe: document.querySelector('#wiki'),
  url: 'http://127.0.0.1:5280',
  app: {
    id: 'org.example.instrument',
    name: '测量程序',
    providers: ['org.example.instrument'],
    capabilities: ['context.read', 'content.open']
  },
  onOpen: async content => {
    // 校验内容版本和真实记录身份，载入并定位完成后才返回。
    await showMeasurement(content.data.recordId, content.data.time);
  }
});
await connection.ready;
await connection.setContext(currentMeasurement);
// 关闭记录或当前内容不可用时清空上下文：
await connection.setContext(null);
// 容器销毁时：
connection.dispose();
```

SDK 自动设置 iframe URL、随机会话与握手。iframe 需要运行脚本、保留同源存储、下载文件及按用户点击打开来源窗口的能力。WebBench 的 `MeWikiEmbed` 是完整接入示例。

`context.read` 的方向是 **MeWiki 读取外部程序主动提供的当前内容**；它不允许外部程序读取笔记。`content.open` 允许 MeWiki 在用户点击卡片时，要求外部程序打开指定内容。上下文更新只更新临时可插入内容；不会静默写入笔记。用户在插入菜单中明确选择后才保存。

## 通信约定与错误

协议名 `mewiki.integration`，当前主版本 `1`。每条消息包含 `protocol`、`version`、随机 `session` 和请求 `id`；响应使用 `replyTo`，返回 `result` 或 `error`。

- `embed.ready` / `embed.connected`：交换程序身份与已开放能力，确认连接就绪。
- `context.set`：外部程序提供或清空当前内容。
- `content.open`：由用户点击发起的来源打开操作。

双方核对准确的 `origin`、发送窗口和会话，不使用 `*` 接收结果。请求受大小与超时约束；同一会话内的近期重复请求不会重复执行。未知操作返回 `unsupported_method`，业务失败返回 `request_failed`，连接关闭会拒绝待完成请求。主版本不匹配时不能接通，应升级对方程序。不要绕过这些检查或为旧后台增加兼容请求。

## 注册新插件

1. 在独立插件目录创建 `manifest.json`，声明 API v1、稳定 `id`、包版本、能力与各内容类型。完整例子为 `examples/plugins/measurement/`。
2. 声明每种类型的 `schema`、`view`、可选 `picker` 与 `source`，通过作者工具校验、打包，再从文件安装，不改核心注册表或增加专用 React 分支。随附插件只增加 `plugins/<名称>/manifest.json`，也使用相同解析器。
3. 外部程序声明相同的 provider，并通过已有宿主 SDK 提供上下文、响应用户点击的定位请求。
4. 验证错误版本与身份拒绝、各内容类型独立校验、无插件仍可读、保存及导出往返、用户点击才打开来源及取消后无写入。操作步骤见[插件开发入口](../plugins/README.md)。

核心只保存通用 JSON 和用户内容；各插件不得直接修改其他插件的资料，不得自动读取或覆盖用户文件。

已启用插件的插入入口由核心 `insertions` 提供：内容类型声明表单时可独立选择，有匹配宿主上下文时可直接插入。选择请求同时携带 provider 与内容类型，有效上下文直接返回，否则打开通用表单。取消、停用、卸载、切换插件版本或中止请求返回空结果，不生成占位块。编辑器在完成选择后重新读取最新笔记并核对原插入位置；切换笔记、资料库或编辑模式会中止选择。外部类型仍不作为“更改类型”的目标。

## WebBench 回放插件

标识：`org.mewiki.webbench`；内容类型：`replay-position`；内容版本：`1`。

引用包含 `runId`、`replayId`、`recordDigest`、本地查询服务 `serviceBase`、WebBench 地址 `webbenchOrigin`、物理时间 `time`，以及可选的 `loopId`、`packetId` 和 `eventLabel`。

独立窗口和无当前上下文的内嵌窗口都可插入。WebBench 插件通过本机查询服务的 `GET /api/replays` 读取已有实验与时间范围，选择合法的物理时间和可选环路后构造同一引用。查询有 10 秒期限，取消或修改服务地址会中止旧请求。默认服务地址为 `http://127.0.0.1:8766`，WebBench 为 `http://127.0.0.1:4173`；用户可以在折叠的连接设置中修改，插入成功后在本机记住。只读取实验目录，完整仿真记录不复制到笔记资料库。

内嵌时由宿主执行定位；独立打开 MeWiki 时，卡片生成包含相同地址的 WebBench 链接。WebBench 从查询服务重新校验实验标识、文件摘要、时间范围和数据包归属，等待真实回放查询完成后才报告定位成功。数据被替换、服务未启动或引用失效时显示具体错误，不定位到其他实验。

旧 `evidence` 卡片继续可读。它们缺少文件摘要和服务地址，不能自动推定来源；载入原实验后可重新插入新版引用。

## 多资料库与入口

每个窗口通过稳定的资料库 ID 读取、保存与获取历史。WebBench 的嵌入 URL 使用 `http://127.0.0.1:5280/?workspace=org.mewiki.webbench`；其他宿主可用自己的稳定标识作为 `workspace`。将带参数的完整 URL 传给 `connectMeWiki` 的 `url` 即可，SDK 会保留这些参数。

- `workspace` 标记入口，分别记忆上次选择，省略时为 `standalone`。所有外部程序使用同一规则：已有入口记忆、已设置的入口默认库、原 `default` 库，不按品牌或资料库名称猜选。设置页入口列表来自插件 `workspace` 声明、当前连接和已有默认配置。
- `library=<id>` 明确指定当前窗口的资料库；切换后更新 URL，刷新仍打开同一库。明确指定的 ID 不存在时显示错误，不静默打开其他资料。
- 这两个参数是导航和偏好，不是用户权限或访问控制；仍仅在本机运行。
- 插件安装状态为应用级。笔记、符号、关系、附件和历史属于资料库；外部上下文只在用户主动插入后写入当前库。切换库会取消未完成的内容选择，保留宿主通信连接。

服务配置升级为 v2，保留原 `directory` 代表 `default` 库，增加库列表、稳定 ID 和入口默认项。读取旧 v1 配置不会重写或搬动资料。`GET /api/research-library/catalog` 列表，`POST` 新建/添加，`PATCH` 改名/入口默认项，`DELETE` 只移除登记。其他资料接口通过 `?library=<id>` 固定身份，无参仍指原库；写入同时校验目录归属，迁移与目录登记共用锁。

原库继续使用 `mewiki:research-notebook` 缓存及原 pending 恢复键；新增库使用 `mewiki:library:<id>:notebook` 和独立恢复/通知键。入口记忆为 `mewiki:workspace:<workspace>:library`。资料库切换先保存当前修改，目标失败时保留原工作区，其他窗口不会被一起切换。新增库只使用手册和通用示例，不复制当前研究内容。

## 资料与运行

图片创作可独立打开，画布直接使用导出工作区左侧的画幅；图层、批量图片与作品均由 MeWiki 宿主管理，不向外部宿主开放笔记、字体或图片资源读取权限，宿主 v1 保持不变。个人模板 v2 携带共用图层、固定装饰与字体，作品备份 ZIP 另外包含批次原图和逐图修改；图片创作存储按资料库/插件隔离，独立于笔记资料备份，停用或卸载保留。参见[画布与作品契约](../plugins/API_V2.md#宿主图片创作画布)和[操作手册](../wiki/20-social-export.md#保存图片设计与备份)。

界面字号和正文字号同样为按资料库保存的浏览器偏好，不进入笔记、导出模板或宿主 v1 协议，也不向外部程序传递。独立图文导出页按冻结会话的稳定库 ID 复用外观提供器，操作界面与原文阅读同步字体和字号，不启动笔记控制器；样板和导出捕获使用模板字体及自己的基础字号，避免阅读设置影响图片。应用默认使用本地随附的 Noto Sans SC Variable；首次显示等待字体准备，失败时回退可用字体。行内代码使用普通正文字体，多行代码块保留等宽排版；操作见[字号说明](../wiki/02-workspace.md#分别调整界面与正文字号)与[字体加载](../wiki/02-workspace.md#刷新时字体如何加载)。

用户通过界面设置或图文导出导入的字体按资料库保存，两处共用原件：本地模式沿用附件区，浏览器模式使用按库隔离的持久数据库，完整含附件 ZIP 和迁移包含字体原件。主软件界面选择按稳定库 ID 保存在当前浏览器，与导出模板选择独立；停用导出插件仍可使用界面字体。个人模板文件可携带所用字体并在导入时保存到目标库；模板配置仍需单独备份，界面偏好在新设备需重新选择。此功能由 MeWiki 宿主提供，不增加宿主 v1 或声明式插件的字体读取权限，不传给外部程序；清单 `fontFamily` 仍只允许 `sans` / `serif`。使用步骤见[界面字体](../wiki/02-workspace.md#使用自己的界面字体)与[导出字体手册](../wiki/20-social-export.md#导入与重复使用自己的字体)。

图文导出的背景纹理由 MeWiki 宿主在“样式”分类提供，包含预设、本地图片裁切处理、最多 6 层叠加和“仅页面内边距”范围。每层独立设置，列表上方在前；页边纹理只覆盖四周页面留白，随每页或长图实际尺寸更新。层序、纹理参数和已应用素材随个人导出模板单独备份，兼容原有单层模板，不写入笔记或资料库交换格式；不增加宿主 v1 权限、远程处理或插件脚本接口。使用流程见[图文导出手册](../wiki/20-social-export.md#设置笔记背景纹理)。

词典资料由 MeWiki 管理，宿主 v1 不新增读写权限。版本 8 的术语可选保存 `englishName`、`englishAbbreviation`、`chineseAbbreviation` 与逐条 `aliasEntries: { id, name }[]`；旧 `aliases: string[]` 保留并与记录同步。稳定术语链接可携带本次显示形式，例如 `mewiki-term:<id>?display=full` 或 `?display=alias&alias=<别名 ID>`，缺少参数的旧链接继续显示名称。处理完整资料交换时保留这些可选字段和链接参数，不按当前显示文字重新推断词条身份。

独立与内嵌访问应使用同一 MeWiki 地址（默认 `http://127.0.0.1:5280`）。浏览器按来源保存缓存，`localhost` 与 `127.0.0.1`、不同端口的缓存不是同一个空间。本地资料库由 MeWiki 服务统一管理。

WebBench 的启动器会检查或启动 MeWiki；`MEWIKI_ROOT` 可指定其目录。正式服务更新代码后，重新构建并重启 MeWiki；只更新 WebBench 适配时重启 WebBench 即可。开发调试可以分别运行两个项目的 `npm run dev`，用 `VITE_MEWIKI_URL` 指定 MeWiki 地址。

旧本地资料库可在 MeWiki 设置中连接原目录。旧浏览器笔记在 WebBench 的“旧笔记迁移”中导出含附件 ZIP，再在 MeWiki 的设置中恢复。导出代码由 MeWiki 提供，只在用户点击后读取 WebBench 自己的缓存和附件，不删除旧资料。迁移必须在原有 WebBench 地址及浏览器配置下操作。

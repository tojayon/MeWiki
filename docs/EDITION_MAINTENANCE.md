# 社区版与服务版维护

公共功能以 [MeWiki](https://github.com/tojayon/MeWiki) 为来源。独立服务版从明确的公共提交整合更新，并保留账户、在线存储、配额及运营部署的适配。两个工作目录不会自动复制文件，也不通过相对路径直接引用彼此的源码。

## 功能写在哪里

- 笔记编辑、词典、公式、地图、引用、资料格式、备份交换、通用 AI 和审阅：先在公共 MeWiki 开发。
- 本机文件、目录与字体：放公共本地适配。自托管通用后端可以在未来作为经过整理的独立公共交付，不能直接发布当前服务仓库。
- 账户入口、在线存储接入、访客与配额、官方订阅／运营和部署：在服务版维护；通用与官方专属能力逐项决定归属。
- 密钥、恢复私钥、真实笔记、数据库与备份：只放受限本地配置或运维存储，私有 Git 也不提交。

当前保留两套独立仓库及共享 Git 历史，不新增第三份核心副本，也尚未拆成 npm 包。服务界面通过运行模式和存储接口接入同一编辑器；后续改动优先集中在适配层，避免复制编辑器组件。

## 公共功能到服务版

1. 在公共目录开发、更新手册，使用虚构资料完成 `npm run check`、`npm run ai:evaluate` 和相关浏览器检查。
2. 执行 `npm run test:maintenance`、`npm run public:check`，明确提交公共修改。推送后查看 **Community checks**，确认自动检查通过。
3. 在服务版执行 `npm run community:status` 查看已整合版本；`npm run community:fetch` 只更新公共上游信息。
4. 选择已验证的完整公共提交，执行 `npm run community:sync -- --ref <40位公共提交SHA>`。它使用 Git 三方合并，不自动提交、不推送、不部署。有冲突时逐段保留公共能力与服务适配，不能用整文件覆盖解决。
5. 解决冲突后执行 `npm run community:sync -- --continue --ref <同一SHA>`，完成公共基线登记。运行 `npm run community:check`，新出现的共享核心差异必须回到公共版实现，或登记具体适配原因。
6. 在 Windows 本地服务版检查编辑、登录、保存、附件、导入和访客，再运行服务版测试。确认后提交私有仓库，等待自动验证；HK 发布继续由现有手动部署入口选择构建版本。

同步的是完成提交，不包含公共目录未提交的工作。用户资料迁移与源码整合、线上部署相互独立。

## 公开检查与推送保护

```sh
npm run maintenance:install
npm run public:check
npm run test:maintenance
```

安装器在当前仓库的 `pre-push` 中接入版本检查；已有自定义 hook 时拒绝覆盖。新电脑、新克隆目录需要安装一次，脚本不会跟随 `npm ci` 自动改 Git 配置。

公共版只允许推送到指定公共仓库，检查当前源码以及实际待推送的提交历史。误把服务分支合入后再删除私有文件，历史检查仍会拒绝。服务版只允许推送到其私有仓库；公共上游另外关闭推送地址。公共 CI 同时检查本次提交范围的历史，首次分支或手动检查扫描完整可达历史；服务 CI 校验固定基线及明确登记的适配差异。

检查覆盖已知私有目录、运行数据、私钥和常见令牌格式，是防误发措施。新增公开自托管能力时，需要同时审阅公开路径规则和完整待发布历史；不能通过改按钮或开关把已经公开的实现变回私有。

## 工作目录约定

- 主仓库路径保持稳定，用来日常开发。
- 临时专题放所属工程的 `.worktrees/`，命名使用简短功能名。Git worktree 必须通过 Git 创建／移动，不能只用文件管理器改路径。
- 旧迁移副本放 `.archive/`，保留明确用途与日期；验收日志和虚构资料放忽略的 `.mewiki/`。
- 工作区和归档目录不参加 Git、代码搜索、构建包或 Docker 构建。未提交专题代码先保留并核对，确认完整交付后再决定归档或移除。

正式服务地址与产品功能范围见[在线指南](HOSTED.md)。

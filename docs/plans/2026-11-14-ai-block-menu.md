# 内容行菜单发送到 AI

## 目标与交互

在编辑模式的内容块前置菜单中增加“发送到 AI”，沿用左图标、右文字的菜单布局。点击后关闭菜单，把当前实际行附加到现有聊天输入区，并打开／激活当前浮窗或嵌入面板。保留输入草稿，不自动发送请求。尾部插入菜单不显示此项。

复用已有引用、会话、失败重试和逐项审阅流程。与手动选中文字相比，不用猜测渲染文字的源码偏移，也不把整行正文拼进任务要求。普通段落、列表、公式、条件／结论和嵌套标签页中的内容共用入口。

## 数据与边界

- `AiTextSelection.kind?: 'block'` 是 v1 会话的可选字段，缺省仍表示旧文字选区。块引用只保存一个稳定根块 ID 与完整摘要，后代从实际树推导。
- `createAiBlockSelection()` 使用 controller 最新快照和已有可读投影，排除其他笔记的引用展开、插件私有数据、注释和内联附件原件。引用摘要上限 4000 字；截断明确标注，完整内容须通过 `read_block` 读取。附件仍不读取原件。
- 行引用允许当前块／子块的原生 `block-update` 与既有文字 `replace-text`；不允许跨行、条件／结论归属、笔记属性、词典和结构增删移动。字段始终由当前块 schema 推导，工具和流式草稿共用断言；原生先读后改与用户批准保存不变。
- 范围显示“本行内容”，快捷提问对应解释／检查／精简；来源可跳回，引用可移除，刷新后恢复。旧文字选区的展示与权限保持原样。
- 菜单点击在编辑器普通 blur 保存后读取实时 controller 状态，激活位置只使用按钮矩形，不进入资料或模型请求。

## 验收

`blockSelection.test.ts` 检查恢复、库隔离、完整基线、有界安全投影、原生公式建议、流式边界、批准撤回与容器子块范围；`e2e/ai-block-menu.spec.ts` 检查无选区点击、草稿／焦点、刷新、编辑后立即附加、标签子块、公式、条件／结论、英文与键盘操作、尾部菜单及显式发送。专项使用 `playwright.ai-block-menu.config.ts`、`127.0.0.1:5561` 和 `.mewiki/ai-block-menu-*`，仅用虚构笔记与受控 AI 响应。

完成验收还包括 `npm test`、`npm run lint`、`npm run build` 与 i18n 检查；实际结果登记于 `docs/VERIFICATION.md`。

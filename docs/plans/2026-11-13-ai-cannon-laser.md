# 原文、激光删除与文字大炮顺序呈现

目标：每次实时预览及回放先显示完整原文，按正文顺序用激光逐字删除需要移除的文字，再用文字炮弹填入新增内容。重复回放重新恢复原文；保留从当前阅读位置起播的行为、全部后续改动覆盖及原审阅／批准／撤回流程。

采用现有 WAAPI 和 CSS Highlight，不添加依赖。差异组件为旧／新内容提供默认不影响布局的分组；播放期间同组旧／新内容叠在一个排版位置，先呈现原文，激光完成本组删除后切到新文，逐发显现新增文字。激光从大炮炮口指向当前字，按完整 grapheme 推进，不截断 emoji 或组合字符；长文本加快扫描但不漏删。只动画 transform／opacity，文字范围仅控制绘制。

实现顺序：

1. 新增完整 grapheme 删除偏移单测及 Edge 场景，先确认当前实现没有激光和原文阶段。浏览器检查原文无删除线、不提前显示新文、逐字擦除、删除完成前不发文字炮弹、重复播放原文重置、纯删／纯增、实时追加与中断清理。
2. 在 `AiReviewChanges.tsx` 与原生差异组件加入可恢复的旧／新分组，在 `aiCannonTextReveal.ts` 管理原文、删除和新增阶段，停止／退出／失败恢复原来的完整差异。目标采集保留后半篇和长范围起播，不能因旧／新层切换跳回首处。
3. `AiTextCannon.tsx` 共用逐组的“删除→新增”调度，实时片段在删除期间合并为最新值；激光退出和用户滚动取消不能触发迟到的文字发射。自动模式继续尊重减少动态，明确回放继续只为本次启用完整运动。
4. 同步第 22 章、AI 架构、开发／接手和验收记录。运行单测、lint、语言、品牌、构建及相关 Edge；隔离端口 `5555`、`.mewiki/ai-cannon-laser/`、虚构笔记与受控回复，不操作真实资料或正式服务进程，不自动提交。

验收以逐帧绘制和文字像素为准，同时核对模型请求、笔记与会话不被动画写入；正式前端通过标准构建和只读资源比对交付。

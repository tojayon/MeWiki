# AI 选区摘要、来源位置与重复选择修正

用户要求：输入框内的选区为灰底两行摘要，第一行笔记名、第二行原文，两行均单行省略；参考来源文件行移到浮窗标题栏正下方；当前选区／当前笔记／当前资料库的原生范围选择器统一灰底样式。保留完整选区及现有发送、删除引用、跳转原文和审阅权限。

Edge 已复现两条选区入口失效路径：Escape 关闭后清除并重选相同文字，旧 dismissed 签名未清；选字指针手势取消后没有 pointerup，pointerSelecting 持续为真。修正生命周期，在有效选区变化／清空时释放旧签名，监听指针取消、丢失捕获与窗口失焦，并在捕获阶段观察结束事件，避免子控件吞掉释放。仅正文起始手势进入拖选状态。

先在 `e2e/ai-chat-actions.spec.ts` 和 `ai-conversation.spec.ts` 观察上述失败，再局部修改 `AiSelectionToolbar.tsx`、`AiWorkspace.tsx/.css` 与紧凑布局；通过现有语言表提供“当前选区”。同步第 2／22 章、UI 规范、架构及开发接手说明。使用独立 127.0.0.1:5533、.mewiki/ai-context-*、虚构资料和受控回复，验证全部单测、lint、i18n、构建与相关 Edge。保留共享改动，现有资料协议、选区基线和用户批准保存流程不变。

完整 Edge 首轮 115 项通过、1 项失败：新增顶部来源与选区同时存在的 390×230px 场景，来源行占高后底栏被表单裁切。将引用及 textarea 收在局部可滚动内容区，紧凑布局固定发送／停止与底栏；聚焦和尺寸变化只滚动该内容区，不移动正文或聊天历史。鼠标／触屏两项复验通过，输入及按钮实际命中通过；小数像素滚动测量允许 1px 舍入，不改变点击验证。正常窗口继续两行摘要。

补查历史对话恢复后再缩矮窗口，Edge 两种指针模式均观察到输入区不可见：材料容器按 conversationId 重建，需要随同重新绑定局部 ResizeObserver。观察器以 conversationId 为依赖完整清理重绑，测试在新建后返回原对话再缩窗并核对输入命中。设置／多库相邻测试须让 runner 与服务共用同一个隔离 MEWIKI_RESEARCH_SETTINGS；首次 runner 未传此变量产生同名虚构资料库累积，修正隔离配置后重跑，不修改产品逻辑。

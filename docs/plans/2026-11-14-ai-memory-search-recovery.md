# AI 聊天记忆、检索与恢复

用户已同意继续可靠性清单第 4～8 项。本轮在当前工作区增量实现，保留已有修改；不提交、推送或使用真实资料／模型。

## 行为与兼容

1. 完整聊天继续保存于按库、按对话隔离的 v1 会话，不再静默裁成 20 条。显示历史分批加载，复制和编辑仍作用于完整记录。容量到达边界或浏览器写入失败明确报错，保留内存记录。模型上下文单独构建：同服务／模型／资料范围／选区／材料的有效对话提要、用户可编辑的本对话固定要求、近期完整对话。摘要仅为引用资料，不恢复读取权限，不混入失败输出或被编辑消息的后续。
2. 工具契约升至 v5，list_notes／search_notes 返回 items、total、offset、limit、nextOffset，稳定排序；检索按标题、标签与正文相关性返回，附命中块稳定 ID、标签路径和片段。不扩大授权，不以命中代替读取，保持统一读取预算。旧参数继续有效。
3. 本地服务传递经过校验的失败类别、恢复操作和 Retry-After 截止时间。限流等待后由用户重试；配置问题直达设置；网络、超时和服务错误保留原任务重试。刷新保留等待，不自动重发，不切换供应商。流式请求以空闲超时为主并设总时限，保持取消和响应大小上限。
4. runner 发布有界结构化活动：阶段、工具、目标笔记／块、成功／失败／复用。聊天显示简短当前进度和可收起记录，目标可定位，只有工具校验后的 ID 可进入持久化活动。兼容旧 tools 字符串。
5. 固定虚构任务通过真实 runner 与受控 completion 执行，输出机器可读报告，记录完成、越界、重复调用、来源、建议有效性、耗时和用量。离线回归与真实模型质量明确区分；评测脚本不读取用户设置或真实资料。

# AI 原位置逐项审阅与调整实施计划

**目标：** 用户在整篇笔记预览的修改位置直接同意、拒绝或调整建议，连续处理时保留当前笔记和标签。

**架构：** 为完整建议生成稳定的内容位置，统一渲染器在块、标签或属性旁插入轻量图标工具条。拒绝只改变本库会话；调整只替换待审建议的内容并保留原始基线、稳定标识和受限字段。逐项同意继续使用原 controller、基线与 effects；其余独立建议按已验证的批准结果衔接，冲突不覆盖。任务生成中不开放审阅决策。

**技术：** React、TypeScript、Vitest、Edge／Playwright，复用原生正文编辑器、字段 schema 与会话 v1 可选字段。

## 交互选择

采用修改附近的图标条：同意、拒绝、调整。桌面悬停或键盘聚焦时展开，窄屏始终可达；不增设重复说明。正文保持原生渲染，调整时使用现有文字／公式编辑控件及明确字段，不要求编辑 JSON。与只在右侧操作相比，按钮能直接对应内容；与整页进入编辑相比，局部草稿更容易确认保存范围。

## 实施步骤

1. **领域与会话。** 在 `src/ai/` 补先失败测试：拒绝与库隔离恢复、待审调整的目标／ID／基线不变、字段校验与取消、逐项批准后独立建议仍可审阅，后续手改保持冲突。实现纯转换和可选 `rejectedIds` 校验。
2. **位置映射。** 按块、标签、首个属性或正文新增位置映射建议，避免父容器重复按钮；同位置多建议保持独立操作。增加 `review.test.ts` 和 `nativeReview` 的渲染回归。
3. **局部控件与编辑。** 新增图标工具条与临时调整组件；正文沿用原生排版／引用编辑器，结构字段用有标签的表单。保存调整只写会话，确认同意才调用批准流程。运行中、只读、过期和保存错误禁用写入，错误在对应项显示。
4. **连续审阅。** `AiWorkspace` 同步拒绝／恢复、调整和批准状态；单项处理不关闭整篇，不跳转其他笔记，处理完全部项后返回正文。继续保留全部同意、按项撤回、切库取消和刷新恢复。
5. **Edge。** 独立端口／设置／固定构建，虚构笔记验证：两页多处逐项同意拒绝、文字调整后渲染／再同意、调整取消、只读／生成中、刷新恢复、剩余项、逆序撤回、窄屏图标可达和中英文。
6. **交付。** 同步第 22 章手册、架构、开发／接手、开放集成及验收；运行 `npm test`、`npm run lint`、`npm run i18n:check`、`npm run build` 与相关 Edge。保留共享工作区修改，不自动提交，不使用真实资料。

## 实施结果

六步已完成。原位置按钮、局部调整、按库拒绝／恢复与连续审阅接入现有批准和 controller 保存；待审输入未保留时，中间和右侧共同锁定该项操作。对重叠冲突保留保护，同时显示独立建议的实际差异。当前处理单位是完整建议，删除和移动没有正文调整入口，局部草稿需显式保留。

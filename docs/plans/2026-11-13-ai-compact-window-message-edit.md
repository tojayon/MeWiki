# AI 紧凑浮窗、边缘缩放与消息编辑实施计划

目标：按用户要求缩小顶部栏、移除六点拖动图标和右下缩放图标，四边及四角直接缩放；底栏提供收起入口，收起后保留可展开的紧凑栏；用户消息操作在气泡外右下方，支持生成中停止后编辑、重发。

架构：`AiFloatingPanel` 保留 Pointer Capture、rAF 直接绘制与按库偏好，标题栏约 28px，边缘命中区无图标，缩放几何集中于 `aiFloatingPanelLayout.ts`。底栏收起回调传给 `AiWorkspace`，收起只隐藏内容且任务继续。内联消息编辑使用会话 v1 可选草稿，保留普通输入草稿与原选区；重新发送时先保存原对话，创建包含编辑位置之前历史的新对话，原后续消息、完整建议和撤回记录仍可从历史查看，笔记内容不自动回退。

实施与验证：

1. 几何测试先覆盖四边／四角、反向锚点、最小尺寸和视口边界。Edge 先验证顶栏高度、无图标的边缘拖动、底栏收起和触屏；观察缺少实现的失败。
2. 实现紧凑标题、八个透明边缘命中区与键盘操作，沿用气泡避让、取消捕获、临时视口恢复、窄屏菜单及轻量绘制。
3. 在 `chatActions.test.ts`／`session.test.ts` 先覆盖消息编辑分支、坏元数据和持久化。原消息未发送前保持不变；开始编辑取消当前请求，拒绝迟到回复。取消编辑保留原消息和下一条草稿；重发失败保持编辑内容，原有对话保存成功后才切换并请求。
4. 实现消息外操作、内联编辑／取消／重新发送及原选区校验；新请求使用当前可见服务／模型／资料范围，原消息带选区时保持其范围，失效引用要求重新选择。编辑中禁用普通发送，避免并行请求或覆盖草稿；已有建议调整／保存中保持原锁定。
5. 同步第 2／22 章、UI 规范、AI 架构、开发／接手和验收记录；运行全量单测、lint、i18n、标准及隔离构建，Edge AI 与设置、多库、手册、导出相邻检查，目视桌面／窄屏／短窗口。

使用独立 `127.0.0.1:5515`、`.mewiki/ai-compact-*`、虚构资料及受控 AI；保留共享工作区其他修改，不自动提交／推送，不读写真实资料或操作正式服务进程。仅前端变更，标准构建后只读核对正式资源。

实现记录：四边／四角缩放、紧凑标题、底栏收起、用户消息外操作、停止后编辑／分支重发与可选草稿均已接入。只读复核发现的滚动条遮挡和延迟焦点覆盖均先补 Edge 失败断言；长回复还复现编辑框被自动跟随带走，编辑态暂停跟随。生产构建反复复现刷新时早于原生 dialog 打开聚焦，改为只观察祖先 open／inert／hidden，实际可交互后恢复焦点并断开。保留真实鼠标、触屏缩放、刷新／切历史／展开及窄屏可见断言；最终全套结果记录在 [VERIFICATION](../VERIFICATION.md)。

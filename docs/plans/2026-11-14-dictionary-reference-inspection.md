# 编辑模式下查看词典引用

用户要求点击笔记中的术语或符号时打开详情，所在段落等继续渲染。当前 `SourceTextBlock` 和 `ResearchTableBlock` 的捕获阶段先激活编辑器，抢在引用按钮前处理点击；稳定符号引用还会直接跳转词典。

渲染态的有效词典按钮交给自身处理，术语沿用 `ResearchTermPopover`，稳定符号复用 `FormulaSymbolPopover` 并保留当前实例角标。仅明确点击面板中的词典入口才导航。普通文字点击仍激活编辑器；已经进入编辑器后，点击引用或 F2 继续打开当前引用的编辑面板。无效引用仍可从编辑器修复，笔记与附件引用行为保持原状。

先以 Edge 复现，再覆盖段落、标题、列表、提示、表格及标签页，验证鼠标、Enter、Space、Esc 焦点恢复、窄屏、正文编辑与资料无写入。同步第 5、7 章手册及维护入口，完成单测、lint、翻译、构建与相邻 Edge 回归。使用 `.mewiki/dictionary-inspection-*` 和独立端口 5573，仅虚构资料，不自动提交。

复核补充：React portal 的 pointerdown 会沿逻辑父组件继续冒泡，点击详情文字原先仍会激活编辑。以失败回归确认后，外层捕获点击及 pointer 激活都核对真实 DOM 包含关系；详情中的单击、双击选字、原子标题与公式点击均不得切换正文或表格源码。最终结果见 [验收记录](../VERIFICATION.md)。

滚动跳转补充：`useFormulaPopover` 在外部 pointerdown 的捕获阶段关闭面板，此时点击目标还未接收焦点。向取消回调传递实际点击目标，`ResearchReferenceEditor` 对离开整个会话的点击，在下一帧复核新焦点后执行原失焦保存；同一编辑区域保留 live 文档，交由原生点击放置光标。F2 引用面板透传同一目标，Esc 继续恢复引用焦点。`e2e/dictionary-inspection-scroll.spec.ts` 使用 50 项虚构长列表，先复现编辑中关闭详情导致数百像素跳动，再核对桌面／手机、两类词典引用及自动匹配的行内符号、初始渲染／正在编辑／F2、同区 DOM 身份与点击光标、切换另一块后的保存。鼠标点击前核对目标确实未被浮层遮挡。

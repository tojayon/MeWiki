# MeWiki 插件生态分阶段开发路线

日期：2026-11-10，最近更新：2026-11-11。状态：P0 统一契约与 P1 声明式本地安装已实现，另已落地不执行代码的 API v2 图文导出分支；P2–P4 的可执行生态能力仍待实施。架构依据为[社区插件生态设计](../plugins/ARCHITECTURE.md)，现有实现见[插件开发入口](../plugins/README.md)、[API v1](../plugins/API_V1.md)与 [API v2](../plugins/API_V2.md)，实际检查结果见[验收记录](../VERIFICATION.md)。

本文件列出阶段交付、依赖与验收，不是对外 API 承诺。开始某阶段时先核对工作区，为该阶段细化实现计划；未验收的阶段不改成“已提供”。不自动提交或推送。

## P0：统一随附插件契约

状态：已实现。目标：新插件不再到处增加 WebBench 特例；保留当前行为和宿主 v1 协议。

实际入口：`src/plugins/sdk/`、`registry.ts`、`bundled.ts`、`PluginContentPicker.tsx`、`PluginContentView.tsx`、`plugins/webbench/manifest.json`，以及 `src/integrations/IntegrationProvider.tsx`、`ExternalContentCard.tsx`。旧 `webbench.ts`、`WebBenchReplayPicker.tsx`、`ContentPickerProps.ts` 已由声明式流程取代。

已交付：

1. `sdk/types.ts`、`manifest.ts` 和 `runtime.ts` 定义显式数据契约与校验，注册表不再由 WebBench 对象推导类型。
2. 注册、状态、结构和内容测试使用通用测量插件，保留旧状态键和未知内容往返。
3. WebBench 的实验目录、连接、时间边界、环路、卡片与来源都在清单中；核心无品牌分支。多内容类型按 provider、类型和版本分别校验，旧选择仍走取消与插入锚点复验。
4. 资料库入口来自插件声明、宿主连接和已有配置，去除 WebBench 专用入口分支和按库名猜选；设置默认库不覆盖已打开窗口身份。

验收：WebBench 独立与内嵌行为不变，未知卡片和旧状态往返保留；`npm run check` 与插件、手册、设置、多资料库相关 Edge 检查通过。虚构插件用于测试，不自动加入用户默认安装列表。

## P1：声明式内容插件与本地安装

状态：已实现。前置：P0。目标：社区作者可以在独立仓库制作不含可执行代码的内容插件，用户离线安装后使用。

实际入口为 `src/plugins/sdk/manifest.ts`、通用表单与视图、`server/pluginPackageArchive.ts`、`pluginPackageStore.ts`、`pluginPackagePlugin.ts` 和设置页 `PluginManager.tsx`。安装服务只接受本机同源操作，包不进入用户资料库。

- 发布 [API v1](../plugins/API_V1.md)：受限清单、精确 API 版本、按类型的内容 schema、文本字段视图、表单与本机目录、来源 URL 及大小限制。
- JSON / ZIP 安装前显示本地来源、身份、版本、SHA-256 与实际能力；后端检查包路径、大小、压缩与 CRC，不解压执行脚本。
- 支持启停、卸载、手动更新与已安装版本切换；失败保留旧版本和状态，成功换版需重新启用。摘要包不可覆盖同版本，跨进程锁、空锁中断恢复与原子登记保留安装数据。
- 作者工具 `plugin:validate`、`plugin:pack` 与 `examples/plugins/measurement/` 已入库，示例不自动安装到用户应用。

验收：本地包首次安装、错误包拒绝、随附身份与连接别名冲突、并发与中断恢复、升级失败保留旧版和状态、卸载保留内容、跨窗口停用均有测试。路径穿越、符号链接、大小写路径冲突、压缩炸弹、恶意 schema 和 URL 有拒绝用例。表单及已安装卡片不依赖外网；本机目录与来源定位仍依赖用户启动相应服务。尚无目录认证或联网更新，不把本地文件来源当作发布者认证。

## P1 扩展：声明式图文导出

2026-11-11 新增的数据贡献分支：API v2 声明模板与画幅，官方“社交图文导出”与 `examples/plugins/publication/` 共用执行链路。宿主固定所选笔记快照，解析词典、公式、引用、本地图片与图表，再使用本机 Edge 生成 PNG/JPEG、长图和多页图片 ZIP；预览复用成品。个人模板按库与插件隔离保存，可单独以含内联图片的 JSON 迁移，卸载保留。

此分支没有第三方代码，不依赖 P2 的隔离代码运行环境；不因此放宽现有安装器对脚本和任意包资源的拒绝。只支持数据模板的通用导出入口，通用命令/面板、导入器、HTML/PDF 与可执行导出器仍未开放。实际契约及限制见 [API v2](../plugins/API_V2.md)，操作见[图文导出手册](../wiki/20-social-export.md)。

## P2：隔离插件运行环境与最小插件 API

前置：P1 已验收。目标：为需要自定义选择、转换与界面的插件提供受控运行方式，再允许安装可执行包。

拟新增插件运行宿主、消息 broker 与公开类型入口；和现有 `public/integration/mewiki-host.*` 分开。先设计跨边界身份、权限、取消和超时测试，再实现 iframe/Worker 启动，不先把下载代码放进主页面。

- 冻结第一组能力：只接收获准上下文、返回候选内容、显示隔离视图和提出用户触发的来源打开请求。
- 宿主控制消息通道、会话与贡献释放；切库撤销旧库授权，失败只停用对应插件，提供恢复模式。
- 验证 CSP、网络代理、存储隔离和所有本地 API 的访问边界。普通 Worker、Node `vm` 或 manifest 权限声明不能单独满足隔离要求。
- 发布可独立使用的类型、最小示例、开发调试与打包工具。API 包名与发布方式在这一阶段确定，不预写不存在的安装命令。

验收：恶意插件读主页面 DOM/存储、直连资料库和附件、伪造身份或库 ID、重放请求、滥发消息、超时、崩溃和迟到响应均被限制；内容仍能正常往返保存。未完成隔离对抗验收前，生产安装器继续拒绝可执行入口。

## P3：编辑器命令、面板与导入导出

前置：可执行贡献要求 P2 已验收；上述声明式图文导出分支独立推进，不以此为前置。目标：同一 SDK 支持用户需要的编辑器增强，不要求社区改 MeWiki 源码。

扩展插件贡献登记与现有编辑入口；修改界面前阅读 `ResearchNotebook.tsx`、公共选择组件、`ResearchReadOnlyContent.tsx` 与设置页现有逻辑。资料提交仍由原 controller 管理。

- 命令贡献：可用条件、菜单和快捷键冲突、忙碌与取消、停用后入口释放。
- 面板贡献：主题、焦点、键盘、尺寸、窄屏收纳与独立错误反馈；不注入主编辑器 DOM 或 CSS。
- 导入导出：用户选择输入与资料范围，插件返回候选数据，核心校验、预览、确认和提交；支持取消、版本冲突及完整附件保留。
- 提供一个通用编辑器增强示例，优先选择“用户选中内容转换并预览插入”，再实现导入器或导出器，避免一开始开放任意写库。

验收：中文输入、撤销与焦点、只读模式、重复执行、取消、切库、保存失败、冲突、插件停用及窄屏都有相关 Edge 检查。插件不得读未授权库或覆盖未知块；用户拒绝导入后原文和附件不变。

## P4：社区目录与作者发布流程

前置：本地安装、版本管理与相应运行能力已验收。目录元信息规范可提前讨论，联网安装不能绕过 P1 安装器和 P2 权限模型。

- 维护独立的静态目录仓库，PR 审核 ID、作者归属、许可证、兼容范围、能力、版本文件和摘要。
- 下载复用本地安装器；设置页提供发现、版本详情、安装与手动检查更新。官方和社区包使用相同校验与授权流程。
- 定义验证发布者、撤回版本、失联插件、兼容性废弃和问题报告流程；用户数据不进入目录。
- 给作者提供模板、构建和发布检查；在独立示例仓库验证从开发到安装的完整流程。

验收：目录不可用、缓存、下载中断、摘要不符、恶意重定向、撤回、权限增量和旧版本回滚都有结果明确的测试。断网不影响已有插件使用，撤回不删除笔记。不把“出现在目录”或包自报的前缀视为安全或官方身份凭据。

## 每个阶段的收尾

运行 `npm run check` 和相关 Edge 用例；改动资料传输或备份时增加对应往返检查。记录实际结果、平台、未验收项与仍是提案的部分。更新 `docs/plugins/`、`docs/integrations/README.md`、实际涉及的 `docs/wiki/`、`docs/DEVELOPMENT.md` 和 `docs/ROADMAP.md`；涉及正式服务代码时构建并重启经过身份核对的本项目服务。

阶段完成条件是独立开发者和普通用户能按文档复现对应流程。P0、P1 的实现和验收已记录，API v2 数据导出在独立分支推进；P2–P4 的代码执行、通用编辑器扩展及社区发现仍不能作为当前能力使用。

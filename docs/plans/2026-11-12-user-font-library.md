# 用户字体资料库实施计划

> 在当前共享工作区接续实现，保留已有修改，不自动提交；沿用用户暂不重启正式服务的选择。

**目标：** 用户在图文导出中导入字体一次，随后可从当前资料库反复使用、下载原件，并通过完整附件备份或个人模板转移。

**架构：** 字体原件沿用附件的摘要标识、分片上传、完整性校验及本地 assets 保存；新增当前资料库的字体目录查询。浏览器暂存字体使用按稳定资料库 ID 隔离的 IndexedDB，与普通附件共用存储实现；连接本地目录和完整附件备份时带上字体。导出参数仅保存字体摘要，实际请求与可携带模板另附经过校验的字体数据，不给插件开放路径或远程字体。

**技术：** React、TypeScript、IndexedDB、现有资料库附件协议、FontFace、Edge、Vitest / Playwright。

## 方案选择

- 采用资料库附件保存原字体，支持 TTF、OTF、WOFF、WOFF2，单文件最多 100 MiB；同字节摘要去重。与仅保存浏览器临时 URL 相比，能持续使用并随本地资料移动；与每份个人模板都保存完整字体相比，日常模板只存引用，避免重复占用。
- “样式”内保留统一字体选择框，分内置字体与资料库字体，旁边提供导入和下载原字体的纯图标按钮。导入后自动选择，刷新后仍列出。不给正文增加字体改写设置。
- 样板和正式图片使用相同字体资源与字体名；原生捕获也等待字体加载，保证换行与分页一致。字体缺失、损坏或浏览器不能解码时明确提示，不将备用字体冒充导入成功。
- 完整附件备份包含字体，JSON 资料备份只含正文仍不含原件。导出个人模板会附带该模板字体，导入时先保存到当前库再保存模板；旧无字体模板继续兼容。也可下载原字体在其他应用使用。
- 字体上限扩大至 100 MiB 后，模板交换文件同步扩大至 140 MiB，含字体的图片导出请求扩大至 160 MiB，以容纳 Base64 编码；正文内容仍保持 32 MiB 上限。

## 实施与验收

1. 先增加失败测试，覆盖二进制字体格式、大小、摘要匹配、请求与旧模板兼容，拒绝 URL / CSS 注入。
2. 扩展现有附件 MIME 与头校验，添加本地字体列表与按库浏览器字体存储；验证重开、去重、跨库隔离、完整备份恢复与连接迁移。
3. 实现字体导入、读取、浏览器解码、资源加载及原件下载；接入样式选择、样板、原生捕获和最终渲染，覆盖无效文件与取消卸载边界。
4. 给个人模板的文件交换增加可选字体资源，保存的模板参数继续只含摘要。验证带字体与旧无字体模板的往返。
5. 更新第 15、20 章使用手册、开发与接续说明及相关接口文档；运行完整单测、代码检查、翻译检查、构建和隔离 Edge 验收，目视核对桌面与窄屏。
